# 편집형 PPTX 생성과 검증

이 참조는 일반 PPTX 요청을 편집 가능한 PowerPoint 객체로 제공할 때 사용한다. Marp 원본은
콘텐츠·슬라이드 순서·색·타이포그래피의 기준이며, HTML/CSS를 픽셀 단위로 변환하는 대상이
아니다. 정보 보존과 편집 가능성을 픽셀 동일성보다 우선한다.

## 런타임 간 동일 계약

Codex와 Claude Code는 생성 도구만 다르고 최종 산출물 계약은 동일하다. Codex는
artifact-tool, Claude Code는 PptxGenJS를 기본 엔진으로 쓰지만 네이티브 객체 매핑, 발표자
노트, 구조 검사, 모든 슬라이드 렌더 QA와 실패 시 자동 폴백 금지는 똑같이 적용한다.

## 의미 객체 매핑

| Marp 콘텐츠 | 네이티브 PPTX 표현 | 허용되는 래스터 사용 |
|---|---|---|
| 제목, 부제, 본문, 목록 | 편집 가능한 텍스트 상자와 문단/목록 | 없음 |
| 표 | PowerPoint 표 또는 셀별 편집 가능한 도형 | 없음 |
| 차트와 수치 | 네이티브 차트. 불가능하면 편집 가능한 도형과 데이터 출처 | 차트 스크린샷만으로 대체하지 않음 |
| Mermaid/정보성 다이어그램 | 편집 가능한 도형, 라벨, 커넥터 | 복잡한 장식 배경만 가능 |
| LaTeX 수식 | PowerPoint 네이티브 Office Math(OMML) 수식 객체 | 없음 |
| 사진, 로고, 질감 | 이미지 객체 | 가능 |
| 발표자 노트, 각주, 출처 | 노트 또는 슬라이드 하단의 편집 가능한 텍스트 | 없음 |

LaTeX 수식은 [editable-equations.md](editable-equations.md)의 별도 계약을 적용한다. 복잡한
SVG처럼 완전한 네이티브 재현이 어려운 장식 요소만 제한적으로 래스터를 허용하며, 전체 정보
슬라이드를 한 장의 이미지로 만들지 않는다.

## 슬라이드 메시지와 정보 밀도 계약

- **한 슬라이드에 하나의 메시지**를 제목과 핵심 시각으로 전달한다. 제목은 주제명이 아니라
  청중이 기억해야 할 결론으로 쓴다.
- 화면 문구는 발표용으로 간결하게 다듬고, 원문의 세부 근거·수치·방법·출처는 발표자 노트에
  보존한다. 외부 근거에는 노트의 `[Sources]` 블록을 사용한다.
- 내용의 양과 중요도에 맞는 의도적인 여백을 둔다. 내용이 적다는 이유로 한쪽에 몰아두거나
  의미 없는 장식으로 채우지 말고, 반대로 과도한 빈 공간이 남으면 핵심 시각을 키우거나
  관계가 있는 설명 예시를 추가해 구도를 다시 잡는다.
- 여러 작은 카드로 화면을 쪼개는 장식적 대시보드보다, 메시지를 가장 잘 설명하는 하나의
  주된 구성과 필요한 보조 설명을 사용한다.

## 의미에 맞는 시각 선택

데이터가 있다는 이유만으로 임의의 차트를 만들지 않는다. 정보의 관계를 먼저 분류한 뒤 아래
기본 표현을 선택하고, 원본 값이 표현을 지지하지 않으면 차트 대신 텍스트나 표를 사용한다.

| 정보 의미 | 기본 시각 |
|---|---|
| 일정, 기간, 병렬 작업 | 간트 차트 |
| 커뮤니케이션, 전달 순서, 단계 | 순차 흐름 다이어그램 |
| 시간에 따른 추세 | 선 차트 |
| 값의 분포 | 히스토그램 |
| 전체의 구성 비율 | 파이/도넛 차트 |
| 항목 간 비교 | 막대/표 |
| 선택, 우선순위, 조건부 의사결정 | 매트릭스/흐름 다이어그램 |

차트 크기는 메시지의 중요도와 라벨 수에 맞춘다. 주된 근거인 차트는 읽을 수 있을 만큼 크게
배치하고, 보조 차트는 축·범례·데이터 라벨이 축소되지 않는 범위에서만 작게 쓴다. 빈 공간을
채우기 위해 차트를 과도하게 키우거나, 여러 차트를 한 장에 작게 밀어 넣지 않는다.

## Codex 네이티브 생성 경로

Codex에서는 `presentations:Presentations` 스킬을 먼저 읽고 그 워크플로를 따른다.
`@oai/artifact-tool`로 로컬 PPTX를 만들고, 제목/본문/표/차트/도형/커넥터를 각각 네이티브
객체로 추가한다. 기존 Marp의 `--pptx` 결과를 최종 편집형 파일로 쓰거나 그 위에 덧그리지
않는다.

Claude Code에서는 `PptxGenJS`를 사용하고 [pptxgenjs.md](pptxgenjs.md)의 설치·생성·검증
절차를 따른다. 다른 런타임에서는 동등한 네이티브 PPTX 생성 도구를 사용한다. 그런 도구가
없으면 사용자에게 편집형 요구를 충족할 수 없다고 알리고, 비편집형 Marp export의 제한을
설명한 뒤 명시적 동의를 받는다. 동의 없이 `marp --pptx`로 바꾸지 않는다.

## 필수 생성·QA 순서

1. **인벤토리**: Marp 슬라이드마다 제목, 문단, 목록, 표, 차트, 다이어그램, 이미지, 노트와
   출처를 기록한다. 정보성 요소를 이미지 한 장으로 합치지 않도록 매핑을 정한다.
2. **네이티브 재구성**: 위 매핑에 따라 PPTX 객체를 만들고, 사진·로고·질감만 이미지로 삽입한다.
   차트가 네이티브가 될 수 없으면 편집 가능한 도형과 수치/출처를 남긴다.
3. **구조 검사**: 산출물에 다음을 실행한다.

   ```bash
   python3 <스킬디렉토리>/scripts/inspect_editability.py dist/slides.pptx \
     --require-editable --json dist/editability-report.json
   ```

   보고서에서 텍스트 객체와 필요한 표·차트·도형/커넥터를 확인하고, `image_only` 슬라이드가
   있거나 검사 명령이 실패하면 원인 슬라이드를 재구성한다.
4. **모든 슬라이드 렌더 QA**: `presentations:Presentations`의 렌더 도우미(또는 동등한 PPTX
   렌더러)로 **모든 슬라이드**를 이미지화하고, 각 페이지를 전체 크기로 하나씩 확인한다.
   자동 레이아웃/오버플로 검사와 육안 검사를 함께 사용해 다음 결함을 찾는다.
   - 의도하지 않은 겹침과 콘텐츠 영역의 경계 침범
   - 텍스트·표·차트·이미지의 잘림
   - 한 줄이어야 하는 제목 줄바꿈과 고립된 단어/기호
   - 자동 맞춤으로 인한 심한 축소와 읽기 어려운 축·범례·데이터 라벨
   - 한쪽 쏠림, 설명되지 않는 과도한 빈 공간, 핵심 시각에 비해 지나치게 작은 차트 크기
5. **수정 후 재실행**: 결함이 있으면 먼저 문구를 줄이고 세부 근거를 발표자 노트로 옮긴 뒤,
   객체 크기와 구도를 조정한다. 폰트를 심하게 줄여 맞추지 않는다. 구조 검사와 모든 슬라이드
   렌더 QA를 다시 실행하고, 결함이 남으면 수정과 검사를 반복한다. 두 검사를 통과한 파일만
   전달한다.

## 명시적 비편집형 예외

사용자가 보기 전용, 수정 불필요, 비편집형 또는 픽셀 충실 PPTX를 명시한 경우에만 Marp의
`marp --pptx` 또는 `npm run build:pptx:flattened`를 사용한다. 전달 시 이 파일이
이미지 기반이어서 텍스트·표·차트·도형을 PowerPoint에서 개별 편집할 수 없다고 명확히 밝힌다.
이는 빠른 시각 전달용 예외이며, 일반적인 PPTX 요청의 기본값이 아니다.
