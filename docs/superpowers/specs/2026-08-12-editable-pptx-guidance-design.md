# Editable PPTX guidance design

## 목적

`marp-slides` 사용자가 PPTX를 요청할 때, 별도 조건이 없으면 PowerPoint에서 텍스트·표·차트·도형을 직접 수정할 수 있는 네이티브 객체 기반 파일을 받게 한다. Marp의 이미지 기반 PPTX 내보내기는 빠른 비편집형 결과가 명시적으로 필요한 경우에만 사용한다.

## 범위

- 기존 `marp-slides` 스킬의 PPTX 라우팅과 검증 기준을 수정한다.
- HTML/PDF 생성 및 기존 Marp 작성 흐름은 유지한다.
- 편집형 PPTX 생성 시 원본 Marp를 콘텐츠·순서·시각 토큰의 기준으로 사용한다.
- 런타임별 네이티브 프레젠테이션 도구 선택 지침을 제공한다.
- PPTX 내부 구조를 검사해 이미지로 평면화된 결과를 탐지하는 재사용 가능한 검사 도구와 평가 시나리오를 추가한다.
- Dear Hair 덱을 실제 통합 검증 대상으로 사용하되, 스킬 자체에는 프로젝트 고유 내용을 넣지 않는다.

## 산출물 계약

PPTX 요청의 기본 산출물은 다음 조건을 만족한다.

1. 제목과 본문은 편집 가능한 텍스트 객체다.
2. 표는 PowerPoint 표 또는 개별 편집 가능한 셀/도형으로 구성한다.
3. 차트는 네이티브 차트로 만들 수 있을 때 네이티브 차트를 사용하고, 불가능한 경우 편집 가능한 도형과 데이터 출처를 제공한다.
4. 정보성 다이어그램은 편집 가능한 도형과 커넥터로 구성한다.
5. 사진·로고·질감·복잡한 장식만 래스터 이미지로 허용한다.
6. 모든 슬라이드를 렌더링해 겹침, 잘림, 예상치 못한 줄바꿈을 검사한다.
7. PPTX 패키지 내부를 검사해 슬라이드별 텍스트·표·차트·도형 객체와 전체 슬라이드 이미지 비율을 보고한다.

## 라우팅

- `HTML`, `PDF`, `Marp preview`: 기존 Marp CLI 경로를 사용한다.
- `PPTX`, `PowerPoint`, `수정 가능한 발표자료`: 네이티브 편집형 경로를 기본으로 사용한다.
- `빠르게 PPTX`, `보기 전용`, `수정 불필요`, `픽셀 동일`: 사용자의 의도가 명확할 때만 Marp 이미지 기반 PPTX를 허용하고 편집 제약을 알린다.
- 런타임에 전용 프레젠테이션 도구가 있으면 그 도구를 우선한다. Codex에서는 `presentations:Presentations`의 로컬 PPTX 워크플로와 `@oai/artifact-tool`을 사용한다.
- 네이티브 생성 도구가 없으면 사용자에게 비편집형 폴백의 한계를 알리고 동의를 받은 뒤 진행한다. 조용히 `marp --pptx`로 대체하지 않는다.

## 스킬 구조

- `SKILL.md`: PPTX 라우팅, 편집 가능성 계약, 생성·검증 루프를 간결하게 설명한다.
- `references/editable-pptx.md`: 객체 매핑, 런타임별 구현 선택, 시각 검증과 OOXML 구조 검사의 상세 절차를 둔다.
- `scripts/inspect_editability.py`: PPTX ZIP/XML을 읽어 슬라이드별 텍스트, 표, 차트, 도형, 이미지 개수를 JSON으로 출력하고 평면화 의심 슬라이드를 실패 처리한다.
- `evals/evals.json`: 기존 `build-pptx` 평가를 편집형 계약으로 강화하고, 비편집형 명시 요청과 기존 Marp 변환 요청을 추가한다.

## 검사 도구 인터페이스

```text
inspect_editability.py <deck.pptx> [--json <report.json>] [--require-editable]
```

- 입력 파일이 없거나 유효한 PPTX가 아니면 비정상 종료한다.
- 슬라이드별 객체 종류와 총계를 JSON으로 기록한다.
- `--require-editable`에서는 다음 조건을 모두 검사한다.
  - 덱에 편집 가능한 텍스트 객체가 존재한다.
  - 정보 슬라이드가 전체 페이지 이미지 한 장으로만 구성되지 않는다.
  - 표 또는 차트가 필요한 평가 덱에는 해당 네이티브 객체가 존재한다.
- 장식 이미지 사용 자체는 실패로 간주하지 않는다.

## 평가 전략

### RED

기존 스킬을 사용하는 에이전트와 스킬 없이 작업하는 에이전트에 다음 압박 시나리오를 준다.

1. `pptx로 빨리 빌드해줘. 나중에 문구와 표를 수정할 거야.`
2. `이 Marp 덱을 PowerPoint로 변환하고 차트 수치를 수정 가능하게 해줘.`
3. `픽셀 그대로면 되고 수정은 안 해도 돼. PPTX로 내보내줘.`

기준선에서 `marp --pptx`를 편집형 결과로 잘못 취급하는지, 편집 가능성을 검사하지 않는지 기록한다.

### GREEN

스킬 수정 후 동일 시나리오를 실행한다. 1·2번은 네이티브 편집형 경로와 구조 검사를 선택하고, 3번만 명시적 비편집형 경로를 선택해야 한다.

### REFACTOR

새로운 우회 표현이나 모호한 라우팅이 나타나면 조건을 일반화해 보완하고 동일 평가를 다시 실행한다. Dear Hair PPTX를 구조 검사와 전체 슬라이드 렌더링에 통과시킨다.

## 오류 처리

- 지원 프레젠테이션 도구가 없으면 제한을 명확히 알리고 사용자 동의 없이 비편집형 파일을 만들지 않는다.
- 구조 검사가 실패하면 산출물을 전달하지 않고 원인 슬라이드를 재구성한다.
- 시각 렌더링에서 겹침이나 잘림이 발견되면 객체 수를 유지한 채 레이아웃을 수정한다.
- 원본 Marp와 네이티브 PPTX 사이에 표현 차이가 있으면 정보 보존과 편집 가능성을 픽셀 단위 동일성보다 우선한다.

## 비범위

- 임의의 Marp HTML/CSS를 완전 자동으로 PowerPoint 객체로 변환하는 범용 변환기
- 모든 SVG·Mermaid·수식을 완전한 네이티브 PowerPoint 수식이나 SmartArt로 변환
- 기존 HTML/PDF 빌드 경로의 디자인 변경

## 완료 조건

- 기준선 실패가 기록되어 있다.
- 수정된 스킬이 세 평가 시나리오를 올바르게 라우팅한다.
- 검사 도구의 정상·실패 테스트가 통과한다.
- Dear Hair 편집형 PPTX가 구조 검사, 오버플로 검사, 전체 페이지 시각 검토를 통과한다.
- 기능 브랜치가 자체 리뷰와 CI를 통과하고 PR로 병합된다.
